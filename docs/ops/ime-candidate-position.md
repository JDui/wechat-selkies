# 2.03 输入法候选窗定位

基线：`AXiVer` / `fe2b88b87ebab9cfea2bed84d99263f4a1b26dc9`（2.02）。

## 原因

`f17aaf4` 将浏览器输入代理 `#keyboard-input-assist` 固定在视口 `(8px, 8px)`。
`f1a838b`（资源版本 `1.76-ipad-input-20261115`）随后让远端画面点击稳定地聚焦该代理。
因此实际输入位置与本机输入法使用的候选窗锚点分离。

## 修改范围

新增 `src/selkies-ime-position.js`，在 `selkies-runtime-overrides.js` 前加载。
定位模块只写现有输入代理的 `position`、`left`、`top` 样式，以 inline `!important`
覆盖旧固定坐标。原输入业务脚本、压缩 bundle 和后端输入处理保持原样。

- 只记录远端画面的主键点击或单触点，鼠标悬停和本地设置控件不会移动锚点。
- 单指操作随后变为双指、滚动或取消时，恢复手势前的锚点。
- 使用 CSS 视口坐标，按显示画面的相对位置保存；重算时不额外乘设备像素比或串流分辨率。
- 处理视频 `object-fit: contain` 的黑边、画面尺寸变化、页面滚动、全屏尺寸变化和移动端可见视口边界。
- 组词期间冻结坐标；结束后下一帧应用待处理的位置变化。失焦、旧代理被替换及缺少组合开始事件的预编辑也有相应恢复。
- Pointer Lock、相对鼠标模式和触摸板模式下的触点不代表远端绝对位置，保留最后有效锚点；忽略触摸产生的兼容鼠标事件。
- 未有有效点击时，输入代理获得焦点后使用可见画面的中心作为回退。
- 不改变输入代理的值、选择区、焦点、DOM 归属或输入属性，不消费事件，不触发额外文字发送。
- 位置仅保存在当前页面内存，不保存输入内容，不增加后台轮询。
- 选中的画面节点暂时移除时，仅在缺失期间观察节点重建，恢复后立即解除该观察。

## 定位精度

本轮恢复的是输入操作落点附近的候选窗锚定。现有协议没有远端文本插入光标坐标，
无法仅从画面点击推算随后方向键、Tab、自动换行或远端窗口移动后的实际文字光标位置。
这些操作之后再次点击目标输入位置即可更新锚点；本轮没有加入文字光标回传协议。

全屏只重算显示几何，不重新挂载输入代理，以免引发失焦或组合取消。
原生输入法最终候选窗的位置与全屏表现需在目标浏览器验收。

## 验证

运行独立定位检查与现有输入回归：

```bash
node tests/test_ime_position.js
node tests/test_ime_delivery.js
node tests/test_ime_ipad.js
node tests/test_ime_partial_commit.js
node tests/test_ime_reconnect.js
node tests/test_ime_activity.js
node tests/test_ime_extreme.js
```

定位检查使用生产模块和可控 DOM 几何模型，验证位置计算、事件时序以及输入业务隔离；
它不模拟浏览器布局引擎或 Windows 原生输入法候选窗。

本轮 21 项定位检查和上述六组输入回归全部通过。联合回放实际输入 guard 后，
发送包、按键消费、活动上报以及输入值的写入与未加载定位模块的基线一致。
同时确认原输入业务脚本、bundle 和后端输入处理相对基线没有差异。

本轮环境的 Chromium 受 `socket() Operation not permitted` 限制，未执行原生浏览器候选窗验收。
未连接运行中的 NAS 容器，未构建或发布 Docker 镜像。

部署后检查：在聊天输入框不同位置点击并输入中文，移动鼠标时候选窗不应漂移；
组词期间改变窗口大小，候选窗不应突然跳动；提交后再点另一输入位置，候选窗应更新。
同时检查全屏、浏览器缩放、单指触摸、中文选词后 Enter、连续重复词以及断线恢复。

## 部署

源码版本和示例镜像标签更新为 `2.03`，新增脚本使用独立缓存版本。
从本分支重建镜像并用现有部署配置重建容器后，浏览器强制刷新一次。
沿用现有配置卷、端口、网络、密码和设备映射。
普通分支推送不会触发当前只监听 tag / 手动运行的镜像发布工作流。
