# 1.82 休眠连接修复、鼠标停留与静息 CPU

## 休眠失败

NAS Compose 使用 1.81 镜像，但没有设置 `SELKIES_CONTAINER_SLEEP`；现场采样确认继承了镜像的 `false`。初始化脚本因此不启动休眠服务，按钮请求得到网关失败。1.81 的隔离测试显式传了 `true`，遗漏了此部署组合。

1.82 完整及增量镜像均默认 `SELKIES_CONTAINER_SLEEP=true`。仍要求配置 PIN 才能冻结工作进程；显式 `false` 保持有效。休眠服务在禁用 / 缺少 PIN 时也提供状态接口，返回具体原因。健康检查覆盖休眠服务。

部署保留现有卷、PIN、端口及 GPU 映射，将镜像改为 `wechat-selkies:1.82` 后重建。若平台保留旧容器的全部环境变量，请显式设置 `SELKIES_CONTAINER_SLEEP=true`，避免继续携带旧 `false`。

## 合并鼠标逻辑

- 鼠标停在页面内不进入视频节流，侧边状态条橙色常亮。
- 离开页面重新开始完整空闲计时，进入节流后恢复彩虹滚动。
- 触屏和笔沿用原逻辑；窗口失焦、页面隐藏清除鼠标停留状态。
- 不改变手动深度休眠：暂停工作进程，回 PIN 页，正确 PIN 恢复。休眠期间不实时收消息，进程内存保留。

## CPU 修复与现场证据

2026-11-15，NAS 第二次 8 秒采样：容器 cgroup 占单核 152.8%，即 8 核总容量的 19.1%；宿主机同期总占用 25.58%。长驻 QQ 进程合计约单核 75%，Selkies 18.22%，Xvfb 14.72%，微信进程合计约 8.7%。长驻进程计数不包含期间退出的子进程，因此不等于 cgroup 总量；不能把全部开销归因于推流。

发现并修复两项额外开销：

1. `get_wm_hints()` 返回 python-xlib `DictWrapper`，不支持 `.get()`。1.80 / 1.81 的优化路径遇到带 WM_HINTS 的真实窗口会异常，退回大量 xdotool / xprop 查询。改用支持的索引访问。原测试窗口没有 WM_HINTS，现已补上。
2. 音频服务持续传送静音 PCM，旧代码把“队列中有缓冲”当成“正在播放”，可持续阻止空闲视频节流。复用现有已解码 PCM 检测非静音活动（幅度大于 0.001），不改动样本、音量或消息接收。短提示音仍触发活动保护，停止更新的活动状态会过期。

同一隔离 Xvfb、两个带 WM_HINTS 的窗口、5 轮查询：旧代码 120 个命令子进程，0.3518 秒 CPU / 0.4527 秒墙钟；修复后 0 个子进程，0.0116 秒 CPU / 0.0168 秒墙钟。此结果仅说明窗口查询成本，不能等同于 NAS 整体降幅。

鼠标停留免节流期间仍会按正常帧率采集；本轮没有更改微信 / QQ 自身线程、网络收消息或强行限制 CPU。现场没有取得可用的 DRM 客户端引擎计数，不能据此确认 GPU 尖峰原因或硬编状态。

## 验证

- 带真实 WM_HINTS 的 Xvfb 焦点、标题、紧急提醒查询通过，断言没有命令子进程。
- 静音 PCM、提示音检测、播放数据不变、活动过期的定向检查通过。
- 鼠标停留 / 离开、橙色 / 彩虹状态、触屏及隐藏 / 失焦回归通过。
- 不显式传休眠开关的隔离容器：真实按钮回 PIN 页、29 个工作进程冻结、错误 PIN 不唤醒、正确 PIN 恢复、健康检查通过。
- JavaScript 语法及镜像内 Python 编译检查通过。

镜像编译及本地验证不等于 NAS 更新后的性能验收。镜像附带 `/scripts/idle-resource-probe.py`，可按需做只读 8 秒采样，结果写入 `/config/logs/idle-resource-probe.json`。
