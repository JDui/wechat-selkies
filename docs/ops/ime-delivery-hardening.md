# 文字输入加固

本轮修复源代码，尚未部署验证真实输入法与微信 / QQ。

## 代码确认的问题

- 旧补丁在所有 `input` 事件中立即 flush、清空隐藏输入框，未区分 IME 的预编辑和最终提交。
- 随附 bundle 只有 `_typeString` 调用，没有该方法实现。旧补丁重试期间，上游其他 `input` 监听器仍可能逐字发送并清空输入框，重试无法保证保留文本。
- 上游窗口键盘监听器会阻止组合输入按键的默认行为；隐藏输入框还有直接转发 Enter / Backspace 的旧监听器。
- 服务端 `co,end` 固定 0.5 秒超时，没有在超时后终止文字注入进程，长句可能继续在后台输入并与后续按键交错。

这些是本地事件处理和注入的缺陷，不能据此认定发生了网络丢包。现有实现也没有远端应用确认文字上屏的回执。

## 当前行为

- 在上游监听器注册前安装窗口捕获监听，覆盖后续创建或重新创建的隐藏输入框。
- 组合期间保留预编辑，只在提交后读取值；组合末尾缺少最终 `input` 时，用一次延迟读取补上。取消组词不发送内容，连续相同文本按两次输入处理。
- 候选词选择用的 Enter、Backspace 等按键留给本地 IME，不阻止默认行为，不传到远端。普通按键与快捷键仍走原链路。
- 复用现有 WebSocket `co,end` 协议，每段最多 128 个 Unicode 码点，不拆开表情或扩展汉字。服务端按原消息循环顺序处理文本和后续按键。
- 未发送内容进入页面内存队列；缓冲超过 256 KiB 或同步发送失败时，120ms 后重试。仅重试尚未被 `send()` 接受的段，避免重复输入。待发送时暂停后续普通按键，避免 Enter 越过文字。
- 连接更换后暂停自动重放并显示提示。先恢复远端输入框，再用“输入法轻修复”，下次按键会尝试发送保留内容。开发排查可调用 `window.selkiesRecoverPendingInput()` 读取尚未发送的内容；不会自动打印文字，也不写入持久存储。刷新或退出页面会丢失这份内存内容。
- 文字注入超时根据长度调整，最长 30 秒；失败记录退出状态或异常类型，超时或取消会终止并回收进程。失败或结果不确定时不自动重放。
- 更新覆盖脚本缓存版本 `1.72-ime-1`。

`send()` 成功只表示浏览器接受了消息，并不证明远端聊天框已经收到文字。跨断线的严格一次投递仍需要额外的确认协议，本次没有宣称提供这一保证。

## 最小验证

运行 `node tests/test_ime_delivery.js` 和 `python -m unittest tests.test_text_injection`，覆盖组词/取消/提交顺序、候选 Enter、重复输入、Unicode 分段、背压、部分发送失败、连接更换，以及服务端超时与取消清理。

这些为隔离事件与进程测试；未启动真实 OS 输入法、X11、微信或 QQ。部署后重点复核：连续拼音选词、用 Enter 确认候选、长句、快速重复提交、表情、短时断线。无须据此执行大规模性能测试。
