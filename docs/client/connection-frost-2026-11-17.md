## 日志结论与连接优化

旧版安装目录只有 WebView2 的配置、收藏夹、会话及存储维护日志，没有 mDNS、网段扫描、导航的阶段计时，因此不能从旧日志推导连接各阶段的真实耗时，也不把源码中的超时上限当作实测延迟。

源码中确认的等待点：

- mDNS 最多等待 4 秒后才开始扫描同网段，扫描结束后才探测外网。
- mDNS 已验证广播 service/name 和目标端口后，还等待一次结果未被使用的 HTTP 身份请求。
- 扫描发现目标后，返回结果前等待其他扫描线程结束。

新版同时启动 mDNS、同网段扫描、缓存内网地址验证和已填写的外网地址探测。内网结果立即使用；外网先返回时最多保留 250 毫秒的内网优先窗口。选定目标后取消其他分支，过期结果不导航、不发布状态。mDNS 浏览在相邻重连之间串行清理，避免上次取消误停下一次浏览。

上次成功的内网地址保存在 `axiver-client-data/last-lan.json`。缓存只作为候选，必须重新匹配 HTTP service/name 并验证当前公布的目标端口。外网栏填写私有 IPv4 时也执行这一验证。身份 JSON 接收完整后立即返回，不再等待服务器关闭连接。SQLite 格式未改变。

本机外网栏和身份接口使用同一私有局域网 IPv4，分别通过 HTTP 3000 和 HTTPS 3001 访问。替换后首次真实启动的新增日志为：

| 阶段 | 耗时 |
| --- | ---: |
| 已填写地址 TCP 可达 | 5 ms |
| 内网候选身份与端口验证 | 13 ms |
| 选定内网目标 | 25 ms |
| 开始导航 | 26 ms |
| 当前 origin 页面加载完成 | 144 ms |

计时起点是连接管理器开始此次发现，不包含进程启动和创建 WebView2 的时间；页面加载完成也不等同于微信登录、视频首帧或输入验收。新版真实窗口标题已更新为 `AXi-SNS-Box`，进程正常响应。

后续计时追加到安装目录的 `axiver-client-data/connection-timing.jsonl`，超过约 1 MiB 后截断重写，不记录截图、Cookie、页面内容或外网 URL。

## 会话控制与磨砂

- 移除内外网切换按钮及相应 IPC。
- 实际点击控制面板和药丸以外的区域时，面板收纳为药丸，约 500 毫秒后再以 320 毫秒动画回到点。外部收纳不抢回被点击视图的焦点。
- CapturePreview 仍只抓取当前远程/工具 WebView。画面留在内存，本地控制层和其他应用不参与采样。
- 仅裁剪控件周围所需区域，复用两级 2× 缩小画布，在约四分之一分辨率上执行小半径高斯模糊；药丸与面板保留各自等效模糊半径。CSS 不再每次重绘都模糊整张远程截图。
- 点约 2fps、面板约 6fps，最小化或隐藏时暂停，已有忙碌标记防止并发截图。

## 用户反馈后的收纳判定修正

用户反馈“控制窗点一下就消失”。原因是把 DOM blur 和 WebView2 LostFocus 直接当作外部点击；内部控件操作和 WebView 焦点变化也可能触发这些事件。初次验证只检查失焦能否收纳，没有验证内部点击应保留面板，覆盖不充分。

修正移除了两条失焦收纳路径。使用 Windows 原生鼠标按下事件的屏幕坐标，换算为主窗口客户区逻辑坐标后，对控制面板和药丸的实际位置做包含判定；只有二者之外的实际按下事件才请求收纳。原事件继续正常传递，不抢焦点，不拦截或重放点击。DOM 内透明区域仍由 pointerdown 检查。仅按键切换焦点或 WebView 自身失焦不触发收纳。

针对性用例新增面板/药丸在不同摆放位置的命中判断，以及隔离原生 WebView2 的打开面板、切换设置页签、聚焦输入框、单纯原生焦点变化、真实内部点击保持展开、真实外部点击收纳并回点。修正后重新构建并直接替换当前使用的 EXE，无备份。


修正验证结果：位置命中判断的 1 项针对性 Rust 测试通过；`verify-connection-frost.mjs ... --click-only` 在隔离原生 WebView2 中通过真实内外点击与单纯焦点变化的正反用例，结果保存在 `screenshots/parallel-frost-click-fix/results.json`。一次完整检查因面板实测 4.48fps 未达到原有 4.5fps 下限而提前失败，未修改帧率阈值；随后只运行与本次修复相关的点击回归。167ms 采样间隔未改，忙碌时会跳过截帧，不能保证所有负载下都达到6fps。
