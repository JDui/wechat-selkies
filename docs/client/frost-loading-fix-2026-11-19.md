# 会话控制浮窗磨砂闪烁修复

2026-11-19

## 问题与来源

回归来自 `f80b9f9` 的局部采样优化。该版本改为先裁剪远端截图，再在四分之一分辨率的画布中模糊。问题发生在采样范围和浮窗布局不同步，以及模糊边缘的初始化处理上。

- 收纳状态的旧纹理约 86px 高。展开面板时立即移除实色背景，但没有从已解码的完整截图重新裁剪；新增区域会直接透出未模糊的远端画面，直到下一次截图。收纳时截图间隔为 500ms，展开后为 167ms。
- 切换到更高的设置页、移动浮窗，也可能超出旧纹理范围。缩小面板时，原生视口会为 300ms CSS 动画保留旧尺寸，而采样过早采用较小的目标尺寸，同样可能露出没有模糊的区域。
- 模糊输出采用不透明画布，尺寸变化后底色为黑色。没有边缘扩展的模糊图在边界产生部分覆盖；连续绘制又未清除上一帧，使暗边在后续帧中逐渐消退。
- 新生成的 PNG 直接写入 CSS，没有等待两张材质图都解码完成，存在替换时的就绪时序缺口。

## 修改

- 缓存最近一张成功解码的远端截图，布局变化时立即重裁，不再等待下一次 CapturePreview。
- 采样覆盖当前可见尺寸与目标尺寸的并集，保留缩小动画需要的区域。判断材质是否可用时也检查目标尺寸，避免增长动画超过仍在解码的旧纹理。
- 模糊前向外复制边缘像素，补足滤波所需的边界；每次处理清除旧画布内容。仍使用两级缩小与四分之一分辨率滤波。
- 两张 PNG 完成解码后同时发布。布局和源帧序号阻止旧结果覆盖新结果，重复布局回报复用已有任务。
- 药丸和面板分别检查覆盖范围。没有完整可用纹理时保留不透明底材质，解码失败时保留上一组完整输出。

本次仅修改客户端材质渲染及相关验证，不修改输入、连接、下载、截图频率、原生窗口布局规则或配置格式。截图继续只在内存中使用。

## 已完成验证

- `node --check`：修改的前端脚本及新增验证脚本语法检查通过。
- `node axiver-client/tests/frost-lifetime.cjs`：执行完整 `shell.js`，使用最小 DOM 几何与可控解码时序，验证最新源帧优先、两张材质原子发布、缓存源图重裁、重复布局复用、过期结果丢弃、解码失败后保留及重试，以及增长/缩小的覆盖范围。该检查不模拟浏览器合成器。
- 离线 Skia 像素回归：在明确补齐浏览器不透明画布初始化/清除语义的测试适配层中，旧版 RGB200 输入的角点首帧为 63，第十帧接近 196，尺寸变化后重新变为 63。修复后两种模糊输出的所有像素从首帧起均为 RGB200、alpha255。
- 同一离线像素检查覆盖重复帧、尺寸增减、视口四边及角落、1×1 和小数尺寸、交替灰度与彩色输入、横纵渐变和非法尺寸。交替彩色输入与全新画布的逐像素比较最大通道差为 0，未出现上一帧残留或填充接缝。
- 推送前复查了完整差异；保留原有 CRLF 文件行尾，使用 `git -c core.whitespace=cr-at-eol diff --check` 检查空白。

## 浏览器与实机验证边界

新增 `axiver-client/scripts/verify-frost-headless.mjs`，用于 100% / 125% / 150% DPI 的 Chromium 回归。它冻结远端截图，覆盖展开、切页、缩小、移动、延迟 PNG 解码超过动画时长、重复布局和过期结果，同时检查模糊图的边缘像素与条纹对比度。

```bash
node axiver-client/tests/frost-lifetime.cjs
node axiver-client/scripts/verify-frost-headless.mjs
node axiver-client/scripts/verify-dock-headless.mjs
```

浏览器脚本需要可用的 Playwright 和 Chromium；可用 `AXIVER_CHROMIUM` 指定浏览器路径。本轮执行环境禁止 Chromium 创建本地进程套接字，自动审批拒绝了扩大执行权限，因此浏览器脚本仅完成语法检查，没有宣称通过浏览器视觉验收。

本环境也没有 Windows WebView2 或 Rust 构建工具。本次提交不包含新 EXE；应用修复需要重新构建并替换客户端。Windows 实机仍应检查首次展开、快速切换设置/连接页、拖动与不同显示缩放下是否存在闪清晰或黑边。
