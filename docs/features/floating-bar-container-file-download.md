# 浮动 Bar 玻璃态重设计与容器文件拖放下载 — 临时目标文档

- **项目**：JDui/wechat-selkies
- **目标分支**：`AXiVer`（直接提交，不创建分支）
- **文档状态**：规划中；本文档是临时实施跟踪文件
- **建立日期**：2026-10-23
- **范围**：浮动 Bar 视觉重设计，以及把容器桌面中的文件拖到 Bar 后下载到本机浏览器
- **视觉依据**：用户在本轮对话中提供的胶囊形玻璃态浮动栏参考图

## 1. 目标与用户流程

把现有浮动 Bar 重设计为参考图所示的横向胶囊形玻璃态工具栏，并新增“容器桌面文件 → 本机浏览器下载”能力。

预期用户流程：

1. 用户在容器桌面中的应用或文件管理器内拖动一个文件。
2. 拖动指针接近浮动 Bar 的扩展感应区时，Bar 进入拖放目标状态：蓝青色外发光、柔和呼吸动画、轻微强调，并显示 **“拖拽到此以下载”**。
3. 文件在有效区域内松开后，容器侧识别被拖入的本地文件 URI。
4. 后端校验文件、复制到受控临时缓存并创建短时下载凭证。
5. 浏览器通过当前会话的受保护下载端点触发附件下载，文件保存由本机浏览器处理。
6. Bar 显示准备中、下载已触发、成功或失败等状态；临时缓存按完成状态与 TTL 清理。

本功能的文件来源是**容器内部**，目标是**本机浏览器下载**，不是把 Windows 本机文件上传到容器。

## 2. 现有实现基线

实现前必须重新核对目标分支当前代码，不得仅依据本文件假定代码未变化。

- 浮动 Bar 主要由 `root/usr/share/selkies/selkies-dashboard/src/selkies-runtime-overrides.js` 中的 `ensureBottomActionDock()`、`ensureBottomActionDockStyle()`、`handleBottomDockAction()` 等逻辑创建和维护。
- 现有 Bar 包含剪贴板发送/接收、微信/QQ 窗口聚焦、分屏、收纳/展开及网速/延迟展示等功能。
- 当前下载浏览器与 nginx 下载目录入口位于 `root/usr/share/selkies/selkies-dashboard/nginx/download-browser.js`、`footer.html` 和 `root/defaults/default.conf`，下载根目录由 `SELKIES_DOWNLOAD_ROOT` 控制，默认目录浏览入口是 `/files/`。
- 现有 `upload-sidecar` 是容器文件上传链路的一部分；上传接口、上传令牌和上传目录不能未经审查直接当作下载实现。
- 现有 PIN 会话鉴权由 nginx 与 session auth bridge 处理。新下载链路必须遵守相同会话边界。

## 3. 必须遵守的约束

1. **不得只做 DOM 拖放假实现。** 浏览器中的 `dragover/drop` 不能自动读取远端 X11 应用内部的文件对象。必须验证真实容器桌面文件拖动链路。
2. **保留现有 Bar 功能。** 参考图用于定义胶囊比例、玻璃质感、透明度、描边、图标风格、间距和光效；不得为了匹配四个示意图标而静默删除现有动作。低频功能可以在经过设计的分组菜单中承载。
3. **不改变现有外部端口映射、密码/PIN 配置和网络模式。** 若确有必要调整内部路由或服务，优先复用现有 nginx 与内部服务路径；任何需要改动部署契约的方案都必须先记录理由。
4. 新下载端点不能暴露缓存目录索引，也不能接受客户端传入的任意服务器路径。
5. 大文件必须流式响应，不得先把整个文件读入浏览器 JavaScript 内存。
6. 下载凭证必须随机、短时有效并绑定当前会话；PIN 会话被接管或失效后，旧凭证不得继续使用。
7. 临时文件不能直接混入普通下载根目录，也不能无限累积。缓存清理必须兼顾正在传输的文件。
8. 任何阶段未通过验证，都必须在本文档记录实际结果、原因、风险与下一步，不得把“代码已写”当作“功能完成”。

## 4. Bar 视觉与交互规格

### 4.1 视觉规格

- 横向居中的胶囊形容器，圆角接近高度的一半。
- 半透明玻璃背景、细腻边缘高光、浅色描边、适度背景模糊和柔和投影。
- 图标采用统一的简洁线性风格，尺寸、线宽、按钮命中区域和间距一致。
- 参考图的蓝色环境只作为视觉参考；实际 Bar 需在当前桌面背景、明暗内容和不同屏幕尺寸下保持可读性。
- 默认态低干扰；悬停、按下、聚焦、收纳、顶部/底部位置和窄视口均需有明确状态。
- 保留现有顶部/底部定位、收纳/展开逻辑以及无障碍标签；图标按钮应有 `aria-label` 和可读的 `title`。

### 4.2 拖放状态机

| 状态 | 表现与行为 |
|---|---|
| 空闲 | 显示常规胶囊 Bar，不显示拖放提示 |
| 进入感应区 | 边缘发光并开始柔和呼吸，显示“拖拽到此以下载” |
| 有效拖放目标 | 持续高亮，明确提示可松开 |
| 文件准备中 | 显示缓存/校验进度或明确的处理中状态，防止重复提交 |
| 下载已触发 | 显示浏览器下载已启动；不得误称文件已写入用户指定位置 |
| 成功/失败 | 显示简洁结果；失败提供可理解的原因并允许重试 |
| 拖离/取消 | 清除拖放状态并恢复常规外观，不产生缓存孤儿 |

动画必须尊重 `prefers-reduced-motion`，且不得干扰远端鼠标、键盘、点击、剪贴板或分屏操作。

## 5. 文件拖放与下载架构

### 5.1 第一阶段必须验证的技术问题

远端桌面由 Selkies WebRTC 在浏览器中呈现。容器应用发起的文件拖放属于远端桌面/X11 的拖放协议；浮动 Bar 则是浏览器 DOM 覆层。两者不是同一个拖放上下文。

因此先制作最小可验证原型，证明容器内支持 XDND 的文件来源能够把 `file://` URI 列表交给 Bar 对应的接收目标，并且指针进入感应区域时可以通知浏览器更新 UI。优先验证原生 X11 XDND 接收目标与浏览器 Bar 几何位置的映射；如果该路线不可行，先记录实验数据和替代方案，不得直接用页面拖放事件冒充已支持远端文件。

需要核对的边界包括：

- 远端 X11 桌面坐标与浏览器视口、视频画面缩放、留边、设备像素比、全屏及分辨率变化之间的转换。
- 原生拖放目标不得在空闲时拦截普通点击或影响现有桌面输入。
- 拖动来源必须是真实文件拖放；普通文本拖动、网页链接、远程 URL、目录拖动不能误判为文件。
- 先用文件管理器内的普通文件验证协议，再验证实际微信/QQ 文件拖动来源。若某个应用不暴露文件 URI，需明确记录该应用的限制。

### 5.2 推荐的数据路径

1. **拖放接收层**：从容器内原生拖放协议获得文件 URI 列表和拖放状态，向前端发送进入、离开、放下、取消等状态。
2. **校验层**：仅接受容器本地文件 URI；规范化路径，检查文件存在、是普通文件、可读且符合大小/并发/剩余空间限制。拒绝路径穿越、目录、无效 URI 和不受支持的来源。
3. **临时缓存层**：把通过校验的文件复制到专用缓存目录，生成随机任务 ID 与短时下载凭证。缓存路径不得由浏览器任意指定，也不得直接暴露真实源路径。
4. **下载响应层**：通过现有同源 nginx/PIN 会话鉴权边界提供受保护的附件下载端点。端点根据随机任务 ID 查找缓存元数据，流式返回文件，设置安全的 `Content-Disposition`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: no-store`。
5. **浏览器触发层**：缓存就绪后，由当前页面创建同源下载请求/隐藏下载链接触发浏览器下载，不打开新标签、不跳离远端桌面页面，也不把整个文件读入 JS 内存。
6. **回收层**：成功传输后延迟清理缓存；浏览器断开、请求失败或容器重启留下的缓存由 TTL 清理器回收。清理器不得删除仍有活动响应的文件。

以上为目标架构。是否扩展现有 Rust/Axum upload sidecar、增加独立 X11 helper，或复用其他现有内部服务，必须在第一阶段根据真实代码结构和原型结果决定，并把决策理由记录在进度日志中。禁止为了实现功能而随意增加宿主机端口映射。

### 5.3 安全、容量与异常处理

- 下载接口继续要求有效 PIN 会话；一次性/短时凭证不能替代会话鉴权。
- 任务 ID 使用密码学安全随机值；客户端不能提交源文件绝对路径来创建下载。
- 下载文件名必须清理 CR/LF、路径分隔符和危险控制字符，并正确支持 UTF-8 文件名。
- 设置可配置的单文件上限、缓存总量/并发上限、最小剩余空间和 TTL；具体默认值在基线调查后确定并写入实现文档/README。
- 缓存写入使用临时文件与原子完成标记；复制失败、空间不足、源文件在拖放后被删除、下载过期、鉴权失败都必须返回明确错误并清理可回收产物。
- 处理重复拖放、同名文件、浏览器多文件下载限制、会话切换和容器重启；不得覆盖普通用户文件。
- 日志可记录任务 ID、文件大小、阶段、耗时和错误类型，不记录 PIN、Cookie、下载凭证或不必要的完整私有路径。
